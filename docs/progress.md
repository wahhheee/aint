## 怎么用

**状态**只用下面五种写法（便于搜索与统计）：

| 标记 | 含义 |
| --- | --- |
| ✅ 完成 | 达到任务的产出要求；可能还有标了编号的小尾巴，写在"缺口"里 |
| 🟡 部分 | 有可用的实现，但缺口明显 |
| 🧱 骨架 | 只有接口、类型、路由或占位，调用时返回"尚未实现" |
| ⬜ 未开始 | — |
| ⛔ 受阻 | 依赖外部条件（如 API Key），条件写在"缺口"里 |

**按任务找代码**：每个未完成点都带任务编号——`TODO(M3-1)` 注释、未实现的工具 `notYet("read", "M3-1")`、返回 501 的路由
`todo("…（M3-1）")`。搜编号即可列出全部相关位置（正则排除 M3-10、M3-11）：

```bash
git grep -nE "M3-1([^0-9]|$)"
```

**更新规则**（人和 AI 都按这个来）：

1. 推进了某个任务：改[任务明细](#5-任务明细)中该行的状态、已有、缺口 → 改[总览](#1-总览)计数 → 在[进度日志](#8-进度日志)顶部加一条（日期、内容、提交）→ 改本文顶部的"最后核对"。
2. 标 ✅ 之前用上面的命令看一遍该编号剩下的 TODO，确认都是可以接受的小尾巴，并写进"缺口"。
3. 代码里新增未完成点写 `TODO(任务编号)：说明`；找不到合适任务的，记入[已知问题](#7-已知问题与技术债)。
4. 需要用户拍板的事记到 [open-questions.md](notes/open-questions.md)，已确认的决策在 [decisions.md](notes/decisions.md)。

## 2. 现在能用什么

`task dev` 后访问 <http://localhost:5173>（假模型，不需要 API Key）：

- **书架与作品**：两部内置示例（《雾港来信》《第一个故事》）、线装书封面、作品详情（简介 / 存档 / 版本 / 校验报告）、开局设置（开局表单、模型、篇幅、推理）
- **阅读页**：静态与生成式开场、流式正文与打字机、选项（数字键）、自由输入与输入模式、斜杠命令面板与作品命令、`/ooc` 场外对话、
  停止（保留已生成内容）、截断自动续写、断线重连与续传、面板（侧栏 / 顶栏 / 浮动）、舞台背景与场景标题卡、插图卡片、样式标签、阅读设置
- **设置**：阅读与外观（实时预览）、存储位置、开发者选项、关于；模型列表（只读）
- **命令行**：`yanyi serve`、`work validate [--json]`、`work prompt`、`version`
- **调试**：假模型脚本（`--fake-llm`）、模型调用追踪（`--trace-llm`）、日志关联 ID（见 [development.md](development.md) 第 3 节）

**还不能用**：真实模型、作品导入、AI 查资料与记忆（read / search / write）、状态更新、上下文整理、分支操作（重新生成、回到此处、修改）、
检查器、用量统计、供应商配置、作品主题、音频、上传图片、访问密码。
